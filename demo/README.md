# Живое демо: DOOM рендерится regex-подстановками

Окно браузера показывает **работающую машину**: слева кадр E1M1 строится в
видеозоне `#F` строки-состояния, снизу — лента реальных подстановок (правило,
что съело, что подставило). Движок — `rvm.exe`: цикл `pcre2_substitute` и
ничего больше; страница лишь читает его экспорт (копии подстрок, как UART).

## Запуск

```bat
py -3.11 demo\start_demo.py
```

Откроется `http://127.0.0.1:8137/`. Остановить — Ctrl+C.

## Что нужно (однажды)

1. **rvm.exe** — `bash scripts/build_driver.sh`
   (кладёт в `%DOOMREGEX_OUT%\build\rvm.exe`).
2. **Снапшот кадра** — строка-состояния машины у входа в рендер кадра 60
   E1M1 (`g2d_fb_snapshot.rvstate`, ~93 МБ). Собирается полностью из
   исходников: см. `scripts/g2d_run.py` (шаги в корневом README), либо
   возьми готовый из релизов репозитория.
3. Правила `vm/rules_rvm.rgxset` уже в репо (196 правил, sha256 в шапке
   файла проверяется драйвером при загрузке).

Флаги: `--state путь` — другой снапшот; `--every N` — частота live-экспорта
(меньше = плавнее лента, чуть медленнее машина).

## Честность

- вся логика — в правилах подстановки, зафиксированных и захешированных;
- драйвер: цикл замен + literal-splice ввода + копирование экспорт-зон;
  аудит: `py -3.11 scripts/audit_driver.py`;
- лента «до/после» — дифф двух копий строки, вычисленный вьювером НАД
  экспортом, а не машиной.
