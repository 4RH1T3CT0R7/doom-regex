# Контракт честности / The Honesty Contract

Этот проект утверждает: **вся игровая/вычислительная логика исполняется итеративной глобальной regex-подстановкой** (find/replace-all) над одной строкой-состоянием. Это модель алгоритмов Маркова — повторение подстановки до фикс-точки Тьюринг-полно. Host-код — «материнская плата», не процессор.

## Правила (bright lines)

1. **Вся логика — в правилах.** Каждый шаг вычисления = применение правила `(паттерн, replacement)` к строке-состоянию. Никакой семантики программы в драйвере, визуализаторе или скриптах запуска.
2. **Правила фиксируются до запуска.** Набор правил (`.rgxset`) генерируется заранее, хешируется (SHA-256 в заголовке файла) и не меняется во время исполнения. Никакого синтеза паттернов по ходу работы.
3. **Драйверу разрешено только:**
   - применять подстановку(и) в цикле до маркера останова или фикс-точки;
   - копировать байты ввода в literal-зону `|IN:` (splice после литерального маркера, без разбора состояния);
   - перезаписывать литеральную зону часов `|CLK:` текущим временем (аналог RTC-чипа);
   - копировать наружу подстроки зон `<FB>…</FB>` и `|OUT:…` (hex→байты — механическое транскодирование, аналог UART);
   - детектировать останов литеральным поиском `ST:hlt`/`ST:err` или нулём замен за проход.
4. **Драйверу запрещено:** арифметика над разобранным состоянием, ветвление по игровым данным, любой lookup смысла состояния. Аудит: `scripts/audit_driver.py` ищет запрещённые вызовы.
5. **Визуализатор строго read-only** по отношению к состоянию; ввод пишется только в очередь для драйвера.
6. **Запрещены в правилах:** Perl `(?{...})`/`(??{...})`, PCRE2 callouts, любые механизмы исполнения host-кода из паттерна.
7. **Перф-шорткаты обязаны быть эквивалентны.** Любая оптимизация применения правил (in-place splice при длиносохраняющих заменах, windowing по фиксированному механическому правилу) обязана иметь медленный эталонный режим «чистый глобальный s///g», дающий **байт-идентичное** состояние; эквивалентность проверяется в CI.
8. **Несколько правил — честно.** Фиксированная упорядоченная последовательность правил, применяемая по кругу, — это классическая система переписывания Маркова (как sed-скрипт). Один паттерн — частный случай.

## Что считается результатом

Кадр/вывод считается «вычисленным регулярными выражениями», если он получен из начального состояния только применением зафиксированных правил + инжекцией входных байтов по правилу 3. Никаких предвычисленных кадров в состоянии, кроме данных, которые настоящая программа (например, WAD-файл DOOM) и так содержит.
