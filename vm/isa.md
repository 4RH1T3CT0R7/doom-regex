# RVM-1 — нормативная спецификация ISA (v1)

CPU, исполняемая итеративной regex-подстановкой (модель Маркова).

Конвейер фаз (v2, CI-кэш): `PH:0` exec → `PH:1` pcinc → `PH:2` fetch.
Один архитектурный шаг = 3 прохода (взятый переход — 2: exec→fetch).
Текущая инструкция кэшируется в поле `CI:` заголовка; исполнители матчат
опкод по фиксированному смещению (O(1)-отказ), скан `#P` выполняет
только fetch-правило — один раз на инструкцию.

## Строка-состояние

```
RVM1|ST:run|PH:0|CI:xxxxxxxxxxxx|PC:xxxxxxxx|R0:xxxxxxxx|R1:…|…|R7:…
|CLK:xxxxxxxx|IN:<hex>|OUT:<hex>|#D…#Q…#L…#A…#S…#P…#F…#M…#E
```
(одна строка без переносов; здесь разбито для читаемости)

- `CI:` — 12 hex (op+d+s+imm) инструкции по адресу PC; `------------`,
  если слота нет (пустая программа / трап NOSLOT).
- Порядок зон: ROM-таблицы, `#P` программа, `#F` фреймбуфер
  (фиксированный размер — короткие сканы), `#M` RAM (растёт позади всех).

- Слово: **32 бита = 8 строчных hex-цифр**, MSB слева. Арифметика по модулю 2³².
- Регистры `R0..R7`: R0=A, R1=B, R2=C, R3=D, R4=SP, R5=BP, R6/R7=T/U (скретч
  для ELVM-бэкенда). Индексированные теги позволяют правилам адресовать регистр
  цифрой операнда: `R\k<d>:` — backreference внутри имени тега.
- `ST:` run | hlt | err:CODE (BADOP, NOSLOT, WEDGE …). Все правила гейтятся `ST:run`.
- `PH:` 0 = исполнение, 1 = инкремент PC.
- `IN:`/`OUT:` — hex-очереди (драйвер: splice после `IN:`, транскод OUT наружу).
- `CLK:` — периферийные часы (пишет драйвер, литеральная перезапись).

### Константные зоны (ROM, генерируются один раз)

| Зона | Содержимое | Размер |
|---|---|---|
| `#D` | `0123456789abcdef` — преемник цифры = следующий символ | 16 |
| `#Q` | `:xx` для x=0..f — тест равенства пары цифр | 48 |
| `#L` | `:xy` для всех x<y — тест «меньше» пары цифр | 360 |
| `#A` | `:abc=oc'` для всех a,b,cin — полный сумматор ниббла (512 записей) | ~3.6К |
| `#S` | `:abc=oc'` — полный вычитатель (borrow) | ~3.6К |

Позиция: сразу после заголовка, ДО `#P` — все lookup-сканы короткие.

### Программа `#P` (Harvard, read-only)

Слоты фиксированной ширины: `I<addr:8hex>:<op:2hex><d:1hex><s:1hex><imm:8hex>;`
PC нумерует инструкции (не байты). Выборка: lookahead `I\k<pc>:` (лениво).

### Память `#M` (v2.1)

`[<addr:8hex>:<val:8hex>]`, ячейки НЕ отсортированы: правило вставки
prepend'ит новую ячейку сразу после `#M` за O(1) (сортированная вставка
была квадратичной: стек ELVM живёт на верхних адресах). Дубликаты
исключены порядком правил (hit раньше insert). Отсутствующая ячейка = 0.
Референс-эмулятор воспроизводит порядок машины: dict Python хранит
порядок вставки, encode() эмитит reversed().

### Фреймбуфер `#F` (v1.2)

hex-байты пикселей; STORE в окно FB-адресов пишет сюда.

## Опкоды v1

| op | Мнемоника | Семантика | Фаза после |
|---|---|---|---|
| 01 | MOV d,s | R[d]=R[s] | PH:1 |
| 02 | MOVI d,imm | R[d]=imm | PH:1 |
| 10 | ADD d,s | R[d]+=R[s] | PH:1 |
| 11 | ADDI d,imm | R[d]+=imm | PH:1 |
| 12 | SUB d,s | R[d]-=R[s] | PH:1 |
| 13 | SUBI d,imm | R[d]-=imm | PH:1 |
| 20–23 | LOAD/LOADI/STORE/STOREI | память (v1.1) | PH:1 |
| 30 | JMP imm | PC=imm | PH:2 (refetch) |
| 38 | JMPR d | PC=R[d] (indirect: возвраты, computed goto ELVM) | PH:2 |
| 31 | JEQ d,s,imm | if R[d]==R[s]: PC=imm else PC+1 | 0/1 |
| 32 | JNE d,s,imm | аналогично | 0/1 |
| 33 | JLT d,s,imm | unsigned < | 0/1 |
| 34 | JGE d,s,imm | unsigned >= | 0/1 |
| 40 | PUTC d | OUT += младший байт R[d] | PH:1 |
| 41 | GETC d | R[d] = байт из IN, при EOF 0 | PH:1 |
| ff | HLT | ST:hlt | — |

JGT/JLE — псевдоинструкции ассемблера (JLT/JGE с переставленными операндами).
Сравнения беззнаковые: лексикографический порядок fixed-width lowercase hex
совпадает с числовым.

Нормативные уточнения (ревью спеки, wf_c1e26280):
- **JEQ — упорядоченная пара правил**: `jeq_taken` (равенство → PC=imm, PH:0),
  затем `jeq_skip` (op=31 безусловно → PH:1). Симметрично JNE/JLT/JGE.
- **Операнды d,s ∈ [0-7]** на уровне паттернов: цифра 8..f не матчится
  fetch-ом ни одного исполнителя → чистый `err:BADOP` (не WEDGE).
- **PC+1 при PC=ffffffff** — нормативный wrap в 00000000.
- **Сравнение с константой** — 2-инструкционное lowering ассемблера/бэкенда:
  `MOVI R7,imm; Jcc d,R7,target`. **R7 зарезервирован** за материализацией
  констант ELVM-бэкенда (R6 — второй скретч).
- **v1.1 (до Doom, по ревью)**: нативные AND/OR/XOR/SHL/SHR (по nibble-таблице,
  1 проход) и MUL — иначе ELVM-builtins разворачиваются в bit-serial циклы
  (сотни EIR-операций на 32-битное умножение), что фатально на Doom-масштабе.
  Tetris переживает builtins.
- **Идиома сканов**: чтение регистров — ленивое повторение possessive-юнитов
  `(?:[^|#]*+\|)*?R\k<s>:` (откаты только на границах полей, не пересекает
  #-зоны, без магических констант); переходы между зонами —
  `(?:[^#]*+#)+?P` (откаты только на границах зон).

## Схема исполнения правилами

Каждое правило: `\ARVM1\|ST:run\|PH:<ф>\|PC:(?<pc>.{8})` + lookahead-выборка
`(?=.*?#P[^#]*?I\k<pc>:<op-литерал>(?<d>.)(?<s>.)(?<imm>.{8});)` + чтения
регистров лениво-ограниченными lookahead (`(?=.{0,200}?\|R\k<s>:(?<v>.{8}))`)
+ потребляющий хвост до целевого поля. Замена re-emit'ит захваченное с
модификацией. Все прочие квантификаторы possessive.

- **ADD/SUB**: 16 цифровых захватов + цепочка из 8 lookahead-lookup'ов в #A/#S
  (перенос LSB→MSB через captured carry), запись 8 цифр — один проход.
- **PC+1** (`PH:1`): каскад из 8 упорядоченных правил (как plus_carry в BF),
  преемник цифры через #D.
- **JEQ**: захват R[d] одной группой + `R\k<s>:\k<v>` на месте. **JNE**:
  упорядоченная пара (сначала правило «равно → PH:1», затем «op=32 → взят»).
  **JLT/JGE**: альтернация 8 веток префикс-равенство (#Q) + первая-меньше (#L);
  JGE — упорядоченное дополнение к JLT-условию.
- **Трапы** (упорядочены после всех исполнителей): выбранный, но нераспознанный
  op → `err:BADOP`; `PH:0` без слота `I<pc>:` → `err:NOSLOT`; финальный
  catch-all `ST:run` → `err:WEDGE` (тотальность: тихий клин невозможен).

## Трассировка

Архитектурный шаг = состояние в момент `PH:0` (CI валиден, инструкция
готова к исполнению). Проходы PH:1/PH:2 прозрачны. Переход/инкремент на
несуществующий слот «сплавляется» с трапом NOSLOT в том же шаге (и в
машине, и в эмуляторе) — транзиентного `ST:run` с плохим PC не бывает.

## Ввод/вывод и воспроизводимость (ревью G1)

- GETC читает из НАЧАЛА очереди `IN:`; драйверы добавляют новые байты
  в ХВОСТ зоны (FIFO).
- Каждая инжекция журналируется драйвером: `(номер прохода, hex-байты)`.
  Прогон полностью детерминирован тройкой (правила, начальное состояние,
  журнал инжекций); режим `--replay` воспроизводит запись байт-в-байт.
- `CLK:` намеренно НЕ обновляется драйверами на этапе 1 (программе виден
  константный `00000000`); включение часов — решение этапа 2 (Doom), и
  оно добавит записи часов в тот же журнал детерминизма.
